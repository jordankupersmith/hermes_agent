## 2a. Version-pairing invariant — app client ↔ server (READ THIS FIRST)

> **Portable rule for anyone re-running or handing this build to another operator
> (human or AI agent): the media server and every smart-TV/console client must be
> on the same major line. Verify it before debugging playback, and never fix a
> playback failure by downgrading the server unless the client is being downgraded
> in the same change.**

**Why this exists.** A sideloaded TV app is not a thin remote: it ships its own
copy of `jellyfin-web` and talks to the server's playback contract. When the
major versions differ, the library still renders — the REST API used for
posters/*Recently Added* is stable — but **every play request fails instantly**
before `PlaybackInfo` ever reaches the server. There is then *nothing* in the
server log to find, which sends you chasing codecs, transcode settings, HLS
formats and firewall rules that were never the problem.

**How it actually presented here (2026-11-18).** Server `jellyfin/jellyfin:10.10.6`;
TV client `Jellyfin for Tizen 0.1.0 … with Jellyfin-12.z`. Posters appeared on
both Mac and TV; the Mac played fine (browser = matching web version served by
the server); the TV failed every title, including a 20 s H.264+AAC clip that
needs no transcode. Diagnosis came from one query — not from logs:
`jellyfin.db → Devices` showed the client's compile line.

**The invariant, as applied to this stack:**

| Layer | Pinned value | Where it is enforced |
| --- | --- | --- |
| Jellyfin server | `jellyfin/jellyfin:12.4` | `phase5_compose.yaml` image pin, guardrail **G20**, apply **V6** (live tag + `/System/Info/Public`), diag **S5** |
| Samsung Tizen client | `Jellyfin-12.z.wgt` (jeppevinkel builds, compiled against jellyfin-web 12.z) | `Dashboard → Devices` row, manual 10e table |
| Jellyseerr | `fallenbagel/jellyseerr:2.1.0` | compose pin; talks to `http://jellyfin:8096` |

**Verification (read-only, 30 seconds — do this before any playback debugging):**

```bash
# 1. server version the API advertises (want 12.4.x)
curl -s http://192.168.122.10:8096/System/Info/Public | grep -o '"Version":"[^"]*"'
# 2. image actually running (want jellyfin/jellyfin:12.4)
ssh -i /etc/media-vm/deploy_ed25519 -o IdentitiesOnly=yes \
    -o UserKnownHostsFile=/etc/media-vm/known_hosts jordan@192.168.122.10 \
    "sudo docker inspect -f '{{.Config.Image}}' jellyfin"
# 3. client build string the server has seen (want …with Jellyfin-12.z)
ssh -i /etc/media-vm/deploy_ed25519 -o IdentitiesOnly=yes \
    -o UserKnownHostsFile=/etc/media-vm/known_hosts jordan@192.168.122.10 \
    'sudo cp /data/config/jellyfin/data/jellyfin.db* /tmp/ 2>/dev/null; sudo python3 -c "
import sqlite3;c=sqlite3.connect(\"/tmp/jellyfin.db\")
print(list(c.execute(\"select AppName,AppVersion,DeviceName from Devices\")))"'
```

`apply` and `diag` both assert items 1 and 2, so `VERIFY_FAILS=0` already proves
the pairing; item 3 is what tells you *which* `.wgt` is on the TV.

**Rules that follow from the invariant:**

1. **Match upward, not downward.** Upstream moved `10.11.x → 12.0` (2026-09) and
   is at `12.4`; `jeppevinkel/jellyfin-tizen-builds` dropped `10.10.z` and now
   publishes only `Jellyfin-12.z.wgt` and `Jellyfin-10.11.z.wgt` (older assets
   exist only in archived releases). Moving the server forward is supportable;
   pinning it back to an abandoned branch is not.
2. **Treat the DB migration as one-way.** Jellyfin 12.0 changes the schema
   irreversibly. `phase5_apply.sh` therefore tars `/data/config/jellyfin` first
   (fail-closed on space), then steps `10.10.x → 10.10.7 → 12.4` through
   throwaway containers waiting for `Startup complete`/`Kestrel is listening`,
   and restarts the **old** container if any step fails. Re-run apply; do not
   hand-edit the pin.
3. **A full library scan is mandatory after a 12.x upgrade.** Auto-resolved
   alternative versions are dropped by the type change and some titles can
   reappear as *newly added* (manual **Step 10h**).
4. **The same rule generalises** to every embedded-client app in the stack:
   webOS/Tizen/Android TV Jellyfin builds, and any future client that bundles a
   web UI. Check the client's compile line against the server major *before*
   touching codecs, transcode settings, discovery or firewall rules.
5. **Do not confuse it with the library policy.** 1080p H.264 + AC3 5.1 with
   few tracks is still the right shape for household media (transcode cost,
   storage) — but it would not have fixed this failure. `TODO.md` **P2** keeps
   that separate from version pairing.

- **2026-11-20 DESIGN — the KVM guest is an implementation choice, not the security boundary.** The owner wants a future deployment option **without `media-vm`**, and that is acceptable because every guarantee this phase actually relies on is enforced *inside the host's Docker network*, not by the guest.
